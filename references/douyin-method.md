# 抖音公开网页解析流程

此方法来自实际批量归档：15 条视频、6 位博主，合计约 60 分钟。旧 Node 下载器、yt-dlp 的 Fresh cookies/403 路径在该环境失败；公开网页流程成功。这个结果不保证所有视频或未来站点版本可用。

## 请求链路

1. 从分享文本取抖音链接。短链 HEAD 跳转中的 `/video/<id>` 或 `/share/video/<id>` 用于确定身份；无法取得时使用已核对的完整链接或 ID。
2. `GET https://sph.miuistore.com/sph/public/dy-check`，查询参数 `data` 为分享 URL。要求 JSON `error == 0`，取其中 `url`。
3. 打开返回的同站结果页。部分结果页只是壳，HTML 中通过 `$.get("https://apikr.convry.com/sph/public/dy-r?...")` 延迟加载下载区域。读取页面实际给出的地址，不自行拼接它的参数。
4. 确认下载区域含目标视频 ID。按 `分辨率 宽 x 高：` 分区读取 `.douyinvod.com` 下载链接，HTML 实体需解码。
5. 查询参数 `cs=0` 或 `cs=2` 的地址可作为候选；按像素面积和 `br` 排序。不要把参数当成确定的编码名称。
6. 下载到临时文件，ffprobe 检查容器/时长/编码，再用 FFmpeg 完整解码视频和存在的音轨。失败则试下一候选，最多尝试配置的候选数。
7. 需要兼容剪辑软件时转码，再次校验，最后以独占创建方式写入目标，避免误覆盖。

## 已遇到的故障与处理

| 现象 | 处理 |
| --- | --- |
| yt-dlp 返回 403 或 Fresh cookies needed | 使用公开网页方法，不要求导出浏览器 Cookie |
| 结果页只有标题，没有媒体链接 | 检查页面实际包含的 `dy-r` 延迟加载请求 |
| 1080p 地址可下载但 FFmpeg 无法解码 | 尝试其他候选，必要时降低清晰度；不能仅凭扩展名判定成功 |
| HEVC 可播放但剪辑软件兼容不好 | 用户需要时加 `--h264` |
| 解析 ID 与输入不一致 | 停止该条，重新核对链接 |
| 旧媒体地址失效 | 重新解析一次，不长期保存签名 URL |
| 服务 HTML/字段变化或要求验证 | 保留失败记录并检查公开页面；不虚构地址或绕过访问限制 |
